      Testing and CI

      How it is checked

      dbt tests by type

      On every pull request, with no credentials

      • Credential leak scan, blocking the merge
      • 328 Python tests over geometry, the dataset registry, the retention proof and the pack generator
      • Raw zone built from committed fixtures, end to end
      • Each ingest run's manifest reconciled against the Parquet it wrote
      • dbt tests: grain, not null, ranges, relationships and three spatial assertions
      • Warehouse dropped and rebuilt from the Parquet zones alone
      • Every model compiled as BigQuery SQL
      • Context pack drift check, plus ruff and sqlfluff

      By hand: row-for-row parity between DuckDB and BigQuery. Running both engines found five defects that compiling alone could not.

      Operations

      Current status

      Scheduled jobs paused since 23 Oct 2026

      Since 4 October the city has re-sent more than 120,000 311 records a day, about four times the usual volume. 311 history is never pruned, so the raw zone and the daily run's network reads grew past what the free tier allows. The data is current to the pause.

      Resuming waits on a decision record for bounding that growth. The options on the table: deduplicate re-sent 311 rows, compact delta history, or fetch snapshot datasets on their weekly freshness target instead of daily.
