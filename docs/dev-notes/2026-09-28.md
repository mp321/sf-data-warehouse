## Findings

- **The host move did not cause this.** The 27 keys absent from 2026-09-28 are
  ADR-19's 27, and both groups were gone by 2026-09-07, which is old-host data.
  19 are city test records (`123456` NAICS, "Test - Add Tta - Do Not Move",
  1455 Market St Fl 16), last seen 09-02; 8 are erroneous registrations last
  seen 08-22 to 08-25. None reappears under another key. The 09-28 snapshot is
  otherwise normal: 367,495 keys against 366,264, same column set.
- **The 09-17 note verified the new host on `film_locations` only.** Fine as it
  turned out, but `business_locations` is the dataset the prune depends on.
- **`check_snapshots` compares neighbours, so two short runs in a row pass it
  on the second.** Found by an existing prune test (`[a,b]`, `[a]`, `[a]`) the
  first draft broke. Hence ADR-21's per-candidate 2% bound as well as the
  keeper check.
- **A Parquet ledger inside `<table>/` would have been read as data by both
  engines**: `read_sql` globs `**/*.parquet`, and `load.py` gives BigQuery
  `<table>/*.parquet`, whose `*` crosses `/`. `_runs/` escapes only because it
  is JSON, not because of the underscore, whatever the comment above
  `RUNS_DIRNAME` implies.
- A chat recommendation early in the session was ADR-19 option A, already
  refused. Reading ADR-18 and ADR-19 before proposing would have saved a turn.
