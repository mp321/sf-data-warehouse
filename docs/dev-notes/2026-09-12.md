## PLAN-10 step 2: the completeness guard gates the build

Second session of the day, same branch. Step 1's baseline is above and is
unaffected by anything here.

### Scope

PLAN-10 step 2 and nothing after it: `check-snapshots` becomes a `make build`
prerequisite, and `make ci-build` proves on a fixture that a short partition
stops a build. This is ADR-19 step 4's first line, which the ADR and the
Makefile both said had to land before the macro and not with it. Out of scope:
the macro itself (step 3), and CLAUDE.md, which PLAN-10 step 8 owns.

### Changes

`Makefile`

- `BUILD_PREREQS` gains `check-snapshots`, and the one switch becomes two:
  `DERIVED_CHECK` and `SNAPSHOT_CHECK`, each turning off only itself. Ordered
  cheap first, `check-derived` then `check-snapshots`.
- The `check-snapshots` target's comment block said, in capitals, that it was
  not a prerequisite of `make build` and that adding it was step 4's first
  line. Rewritten to say it now is, and to keep the argument for why it gates
  a day early rather than a day late.
- New `CI_SHORT` zone under `data/ci/`, and a proof block at the end of
  `ci-build`.

`ingestion/check_snapshots.py` — the docstring's "It does not gate
`make build`" section, which was the longest passage in the file and is now
false. Rewritten around the same two cases, with the escape hatch and the
three places it runs.

`scripts/short-snapshot-fixture.py` (new, 100 lines) — writes a raw zone whose
newest snapshot partition holds 100 of the previous partition's 500
`grain_key`s, with run manifests that reconcile. Called only by `ci-build`.

`tests/test_check_snapshots.py` — seven tests, in two blocks. Four exercise
`check()`'s exit code over a real zone built through `raw_zone.write_batch`;
everything there before tested `shortfalls`, the pure function, and the exit
code is what the gate actually rests on. Three assert the wiring through
`make --dry-run`.

### Findings

**1. The guard has been running in `ci-build` since it landed and asserting
nothing, and that was structural rather than an oversight.** `ingest.py` dates
a partition from the run's own clock (`ingest_date = started_at.date()`), so
one fixture run is one partition per dataset, and there is no flag to write a
second under another date. Every `make ci-build` since ADR-19 step 3 has
printed "only one partition, so there is nothing to compare it against" for
all five snapshot datasets. That is why the proof needs a purpose-built zone
rather than a second fixture ingest, and it is worth knowing before anyone
tries to make the pipeline fixture two-partitioned to save the extra file.

**2. `make build` exits 2 against a short zone, not 3.** Make reports a failed
recipe with its own exit code, so the guard's 3 never reaches the caller. The
proof therefore asserts two things that are true rather than one that is not:
that the sub-make fails, and that its message names `check-snapshots` as the
target it failed at, which is what distinguishes "the build was refused by the
guard" from "the build broke". The 3 itself is pinned in pytest, directly of
`check()`.

**3. One switch for two guards would have been a live trap.** `DERIVED_CHECK=0`
is documented in CLAUDE.md and is a thing people type when they know the
geography is stale and want to build anyway. With a single variable it would
have silently taken the snapshot guard with it, which is the failure mode where
the escape hatch you meant to use disables the one you did not know about.
`test_each_gate_has_its_own_escape_hatch` pins both directions.

**4. `check_runs.py` passing on the short zone is now executed rather than
asserted.** ADR-19's argument for the guard existing at all is that a mid-fetch
death reconciles against its own manifest, so the check beside it passes by
design. `ci-build` now runs `check_runs.py --strict` on the short zone and
requires it to pass, immediately before requiring the build to fail on the same
zone. If that ever stops being true, the guard's reason for existing has
changed and someone should find out from a failing PR rather than from prose.

**5. The proof is not vacuous, and this was checked rather than assumed.** Run
the same fixture zone through `make build DERIVED_CHECK=0 SNAPSHOT_CHECK=0` and
it builds clean, `PASS=172 ERROR=0`: dbt has no idea the zone is short, because
staging unions every partition and the complete one supplies the missing keys.
So the assertion has something real to catch, and the "today, nothing" half of
ADR-19's reasoning is demonstrable in one command.

**6. The gate costs 11.7s on the bucket zone and `check-derived` costs 77.6s.**
Measured back to back after the step 1 rebuild. A full `make build` against the
bucket is now 2m12s, of which dbt is 34s and the two prerequisites are the rest;
the new guard is about 9% of the prerequisite cost and 13% of what was already
being paid before it. On the local zone and in CI it is milliseconds, because
those zones are one partition per dataset.

**7. `ci-build`'s own pipeline is untouched by the wiring.** It calls
`dbt build` directly rather than `make build`, so the prerequisite never fires
there and the proof block is the only thing in CI that exercises it. Anyone
reading a green `ci-build` should not take it as evidence the gate is wired;
the explicit block is the evidence, and the last line it prints says so.
