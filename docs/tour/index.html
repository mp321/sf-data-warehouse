      • 335 Python tests over geometry, the dataset registry, the retention proof and the pack generator

      • Each ingest run's manifest reconciled against the Parquet it wrote

      • Every model compiled as BigQuery SQL
      • Context pack drift check, plus ruff and sqlfluff

      By hand: row-for-row parity between DuckDB and BigQuery. Running both engines found five defects that compiling alone could not.

      Operations

      Current status

      Scheduled jobs paused since 23 Oct 2026

      Since 4 October the city has re-sent more than 120,000 311 records a day, about four times the usual volume. 311 history is never pruned, so the raw zone and the daily run's network reads grew past what the free tier allows. The data is current to the pause.

      Two things were behind it. Each daily run downloaded about three times the raw zone, because the storage library padded every read to 5 MiB. That is fixed: measured on a local copy, the same reads now fetch about a fifth of the zone. The zone itself still grows without limit.

      Resuming waits on a decision about that growth. ADR-22, a draft, proposes not storing a re-sent 311 row whose only change is a load stamp, which is five rows in six.
